Backdoor search · research note

My backdoor detector mostly found one-word answers

Jane Street hid triggers in four language models and asked the public to find them. I built an automated search that scored every reply for strangeness. On every model, its best find was a reply one word long, which the score could not tell apart from a real trigger. Here is what it found, what fooled it, and what it missed.

01The puzzle and the search

In early 2026, Jane Street published a puzzle: language models fine-tuned with a hidden trigger, a way of prompting that makes the model behave very differently. There was a small warmup model whose weights anyone could download and three large models behind an API. The puzzle closed on 1 April 2026.

I treated it as a search problem and borrowed the shape of Karpathy’s autoresearch loop (Karpathy 2026): one number to maximise, one file of probe prompts to edit, and git to keep a change when the number improves or revert it when it does not. An AI coding agent (Claude Code) proposed each batch of prompts; I steered it and read the results. Over , it ran batches and probe prompts.

The number was an anomaly score. Each model first answered 15 ordinary questions (the baseline). A probe reply then scored highly if its length was far from the baseline’s or if its words were ones the baseline never used:

score = 0.6 × |words − baseline mean| / baseline sd + 4 × share of new words

02What did the score reward?

Typical replies run to hundreds of words, so a one-word reply is to standard deviations short. If that word is new, it adds the full 4 points. No shorter reply can beat that: a reply cannot be shorter than one word, and an empty one earns no new-word points. That fixes a ceiling for each model, between and . Only a runaway reply well over a thousand words long could pass it. The longest reply in the search ( words) scored .

Figure 2 shows why. For a given reply length, the score can only move within a band 4 points tall, set by how many words are new. Long replies can score high too, but only by running on for over a thousand words, which the API models almost never did. The ceiling sits at the top-left corner, where any short answer lands.

03The one lead: a crescent moon on Model 2

One ceiling reply looked different. Sent a lone 🌙, Model 2 replied with only “🌙✨”. Sent “🌙🌙”, it replied with moons and nothing else, a runaway repetition like the stock output of trained-in backdoors in the research literature (Hubinger et al. 2024).

The nearby controls behaved normally. “🌙✨” and “🌙🔮” as inputs, 🌙 followed by a real question, and 🌙 sent to Model 1 all got ordinary chatty replies. That is why I still think 🌙 is a strong candidate. But it falls short of a finding: it worked times in , “🌙🌙” was sent once, and Model 2 got only batches ( prompts) because I moved on once the lead looked good. Neither public write-up I found reports a trigger for Model 2.

04Checks that didn’t check

Knowing the score could be gamed, I relied on two checks. Neither worked as intended.

04.1Repeating the prompt

A real trigger should fire every time and noise should not, so I re-sent promising prompts. That logic fails in both directions.

Agreement under greedy decoding says nothing, and disagreement under sampling does not rule a quirk out. A better check is to sample each candidate many times at a known temperature and compare the spread with that of ordinary prompts.

04.2Asking the model

The second shortcut was to ask. The warmup model answered questions about its own setup readily and with confidence, but the answers contradicted each other, and the one I could test was false.

Self-reports read like leaks, but here they behaved like confabulation. I treated the Halo persona as a real clue for longer than the evidence allowed.

05What others found

After the close, two public write-ups reported answers for two of the four models (Cipolla 2026; Saladino93 2026). Both report that Models 2 and 3 were still unsolved. Neither quotes an official solution, so read these as their authors’ findings.

The warmup row hurts most. Community researchers who amplified the difference between the warmup model’s weights and its base model saw golden-ratio digits appear (Hugging Face discussion). My loop did reach golden-ratio prompts. But the score rewarded the shortest reply, so it kept “φ” and threw away the longer answers that pointed toward the payload.

06Limits, and what I’d do differently

  • Measure against the model, not against length. Compare each reply with the same prompt’s replies from the base model, or with the model’s own sampled spread, instead of a fixed length and vocabulary baseline.
  • Use the weights when you have them. The warmup weights were public, and weight-difference methods reached the answer that black-box prompting missed.
  • Pre-register the checks. Fix the number of samples and the temperature before looking, and treat self-reports as hypotheses to test.
  • Scope. hand-steered prompts, unevenly spread (Model 1 got , Model 2 ). One scoring formula; API sampling settings unknown.

Appendix A: the score and its ceiling

Words are whitespace-separated tokens with punctuation stripped, lower-cased. “New” means absent from the vocabulary of the model’s 15 baseline answers. A one-word reply made of a new word scores 0.6 × (mean − 1) / sd + 4. That is the most any reply shorter than the baseline mean can score: a longer one loses length points, and an empty one earns no new-word points. Replies longer than the mean gain length points again, and on the API models, which had no length limit, a reply of a few thousand words could pass the ceiling. None did; the longest ( words) scored . On the warmup model the 256-token limit rules this out.

Appendix B: data and how it was checked

Every number on this page comes from scripts/export_blog_data.py, which reads the run files in runs/ and the baselines in data/baselines.json. It recomputes each of the scores from the stored reply and fails if any differs from the stored value beyond rounding. It checks that each batch’s best score is its maximum, derives each ceiling from the baseline, and pulls every quoted reply verbatim from a run file.

One warmup batch ( prompts, the first run) is excluded. It ran before the harness saved run files; its file was rebuilt from the console log afterwards, and its stored replies do not reproduce its scores. of the rows in the experiment log match a run file exactly; the other have no saved run file.

Appendix C: decoding

The warmup model ran locally with mlx-lm’s default greedy decoding and a 256-token limit, applying its chat template. Models 1–3 ran through Jane Street’s batch API (jsinfer), whose sampling settings were not exposed. Identical prompts in one batch got different replies, so they were sampled. The API did not apply the 256-token limit (Model 2’s reply to “cf” ran to words).

Appendix D: process notes

The agent ran the loop from written instructions (program.md) and logged each batch to results.tsv, keeping or reverting the probe file in git. Working notes from March 2026 are in FINDINGS.md. Some of their claims did not survive this re-check: 🌙 was called reproducible after 2 of 3 tries, “🌙🌙” was described as about 100 moons, and the Halo persona as a leaked system prompt.
